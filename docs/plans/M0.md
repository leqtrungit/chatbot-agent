## 0. Quyết định thực thi của M0 (đọc trước khi làm bất kỳ task nào)

1. **Xoá để xây, không chung sống**: task đầu tiên xoá `backend/app/` + `backend/tests/` trên nhánh này và scaffold skeleton mới. Code v1 để tham chiếu/port nằm ở nhánh `develop` và git history — KHÔNG giữ hai app song song trong cùng working tree. Frontend giữ nguyên cây, sửa dần.
2. **Ingestion runtime dời sang M1**: pipeline xử lý document cần queue; queue thuần Postgres là sản phẩm của M1 (ADR-1). M0 chỉ có KB/document CRUD + upload file + row `pending`. Document sẽ "nằm chờ" cho tới M1 — chấp nhận, ghi rõ trong API docs.
3. **Đổi tên theo glossary spec**: `Domain` (v1) → `KnowledgeBase`. Mọi code/schema/API mới dùng tên mới.
4. **Keycloak pin version 26.x**; realm config as-code (`infra/keycloak/realm-export.json`), import tự động khi container khởi tạo. Không cấu hình tay qua UI ngoài bootstrap admin.
5. **Schema mới từ migration số 1** (squash — không kế thừa lịch sử Alembic v1): mọi bảng nghiệp vụ có `org_id` NOT NULL + FK + index. API key hash bằng SHA-256 (đủ cho token ngẫu nhiên entropy cao; bcrypt không cần cho key máy).
6. **Org-scoping nằm ở data-access layer dùng chung** (NFR-SEC1): một module `app/core/tenancy.py` cung cấp scoped-session/scoped-query helper mà MỌI service phải đi qua; cấm viết `select(Model)` trần trong module nghiệp vụ (enforce bằng test kiến trúc).
7. **Test authn không phụ thuộc KC container**: backend verify JWT qua JWKS; test dùng RSA keypair tự sinh + JWKS tĩnh (fixture), phát JWT giả lập claim KC. Integration test thật với KC container: một job CI riêng, allow-failure ở M0, bắt buộc từ M1.
8. Mọi commit/PR reference FR/NFR ID (NFR-T2).

## 1. Kiến trúc đích của M0 (khung backend mới)

```

├── core/          # config, db (async engine/session), tenancy (scoped access), security (JWKS verify, principals)

├── orgs/          # Organization model + operator API (tạo/suspend org, đồng bộ KC Organization qua KC Admin API)
```

## 2. Task breakdown

Ký hiệu: `⇐` = phụ thuộc. Mỗi task là một đơn vị giao cho một agent nhỏ, TDD, kèm test list tối thiểu. Executor **không được** tự quyết định lệch spec — gặp mơ hồ thì dừng và báo (escalation về orchestrator/Fable, đúng quy trình đã thống nhất).

### T0 — Reset & skeleton ⭐ (chặn mọi task khác)
Xoá `backend/app`, `backend/tests`; scaffold khung §1 (core/config, core/db, main.py + `/health`); `pyproject.toml` mới: **bỏ `arq`**, thêm `python-jose[cryptography]` (hoặc `pyjwt[crypto]` — chọn một, ghi lại), giữ FastAPI/SQLAlchemy/alembic/pgvector/httpx; alembic init sạch (chưa có migration nghiệp vụ); docker-compose: thêm service `keycloak` (KC 26.x, dev mode, import realm từ `infra/keycloak/`) + postgres riêng cho KC. Test: `/health` 200; app factory boots.
**DoD**: `uv run pytest -q` xanh (suite mới, nhỏ); compose up đủ postgres/redis/keycloak.

### T1 — Keycloak realm as-code ⇐ T0
`infra/keycloak/realm-export.json`: realm `harness`, client `admin-ui` (public, PKCE, redirect localhost FE), client `backend` (bearer-only/JWKS), realm role `operator`, bật Organizations feature; README bootstrap (tạo user operator đầu tiên). Script/smoke: realm import thành công khi compose up.
**DoD**: KC lên, JWKS endpoint trả key, login được bằng user operator tạo tay theo README.

### T2 — Security core: JWKS verify + principals ⇐ T0 (song song T1)
`core/security.py`: verify RS256 JWT qua JWKS (cache + refresh), map claims → `OperatorPrincipal` (realm role `operator`) | `TenantPrincipal{user_id, org_id, role owner|admin}` (từ KC Organizations claim — tên claim chốt theo T1, phối hợp qua orchestrator). `identity/deps.py`: `require_operator`, `require_org_member` (trả TenantPrincipal, 401/403 đúng chuẩn). Test: keypair tự sinh + JWKS tĩnh fixture; token hết hạn/sai chữ ký/thiếu claim/role sai → 401/403; đúng → principal đúng org.
**DoD**: test list trên xanh, không cần KC chạy.

### T3 — Schema & tenancy layer ⇐ T0
Models: `Organization{id, name, slug, keycloak_org_id, status active|suspended}`, `ApiKey{org_id, name, key_hash, revoked_at, rate_limit_per_minute}`, `Agent` (port cột v1 + `org_id`), `KnowledgeBase` (rename từ Domain, + `org_id`), `Document` (+`org_id` denormalized), `DocumentChunk` (+pgvector 768 + HNSW, `org_id`). Migration số 1 duy nhất. `core/tenancy.py`: helper scoped query (vd `org_query(session, Model, org_id)`) — mọi service dùng nó. Test kiến trúc: (a) mọi bảng nghiệp vụ có cột `org_id` (introspect metadata); (b) grep/AST cấm `select(` trần trong modules nghiệp vụ ngoài tenancy layer (NFR-T3 mở rộng).
**DoD**: migration chạy trên postgres docker; test kiến trúc xanh.

### T4 — Orgs module (operator API) ⇐ T1, T2, T3
`POST /v2/operator/orgs` (tạo org + gọi KC Admin API tạo KC Organization + lưu mapping), `POST .../suspend`, `GET .../orgs`. KC Admin API client tách interface để test mock (không gọi KC thật trong unit test). Org suspended → mọi request tenant của org đó bị 403 (check trong `require_org_member`, phối hợp T2). Test: tạo org ghi cả hai phía (KC mock được gọi đúng), suspend chặn request, operator-only (tenant token → 403).

### T5 — ApiKeys module ⇐ T2, T3 (song song T4)
Port v1 sang org-scoped: CRUD dưới `/v2/orgs/{org_id}/api-keys` (tenant admin của đúng org), key hiện một lần, lưu SHA-256, revoke hiệu lực ≤60s (cache lookup TTL — Redis). Dep `require_api_key` mới trả `(ApiKey, org)` làm nền cho M2. Test: port test v1 + case cross-org (admin org A đụng key org B → 404/403).

### T6 — Agents module ⇐ T2, T3 (song song)
Port CRUD v1 → `/v2/orgs/{org_id}/agents`, org-scoped, soft-deactivate (FR-A4). Bỏ phần gán MCP (M2). Giữ gán agent↔KB (bảng link có sẵn trong T3? — bảng `kb_agents` thêm vào T3 nếu thiếu, executor T6 phối hợp qua orchestrator, không tự sửa migration của T3 — thêm migration mới). Test: port + cross-org isolation.

### T7 — Knowledge module ⇐ T2, T3 (song song)
Port KB CRUD + document upload (lưu file + row `pending`; **không** enqueue — ghi TODO M1 rõ ràng), document list/status/delete. Test: port + cross-org isolation + upload file lưu đúng chỗ theo org (path có org_id).

### T8 — Cross-tenant isolation suite (NFR-SEC1) ⇐ T4–T7
Test suite riêng `tests/isolation/`: dựng 2 org + 2 tenant token + 2 api key, chạy ma trận truy cập chéo trên MỌI endpoint đã có (orgs/apikeys/agents/kb/documents) — kỳ vọng 403/404 toàn bộ. Đây là suite sẽ chạy mãi mãi về sau, mọi module mới bắt buộc thêm vào ma trận.
**DoD**: ma trận phủ 100% route đã đăng ký (introspect app routes, fail nếu route mới chưa khai báo trong ma trận — chống quên).

### T9 — CI ⇐ T0 (làm sớm, chạy song song mọi task)
`.github/workflows/ci.yml`: job backend (postgres+redis services, `uv run pytest -q`), job frontend (`npm run build && npm run lint`), job keycloak-integration (KC container + smoke authn — allow-failure ở M0). Trigger: PR + push nhánh làm việc.

### T10 — FE: login Keycloak + port trang ⇐ T1, T4–T7
Thay basic-auth login bằng OIDC code flow + PKCE (client `admin-ui`); org context sau login; port trang Agents/KB/API-keys sang endpoint `/v2/...`; ẩn các trang chưa có backend (playground, dashboard — quay lại M2/M3). Bar: `npm run build && npm run lint` + login thật với KC local.

### T11 — Docs & wrap-up ⇐ tất cả
Cập nhật `progress.md` (bảng status mới theo milestone v2), `CLAUDE.md` (kiến trúc v2, lệnh mới, bỏ mô tả v1 đã xoá), README quickstart (compose up gồm KC). Chạy toàn bộ DoD của M0 end-to-end, ghi kết quả.
